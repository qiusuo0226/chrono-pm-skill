# 需求登记册与追踪矩阵

> 权威正文。检索面见 `requirements/_index.md`（7 列）。本册总览也保持 7 列，细节写在「需求详情」。
> 需求只绑工作包，不写关联待办。一需求可多个 WP。无需求禁止建工作包。
> 确认状态与生命周期分开：未确认可以继续留在清单，但不得组已规划工作包、不得拆待办。

## 需求总览

| Req ID | 标题 | 确认状态 | 生命周期 | 工作包 | 来源 | 优先级 |
|---|---|---|---|---|---|---|
| REQ-[模块]-NNN | [功能内容] | 未确认 / 已确认 / 已否决 | 已提议 / 进行中 / 已交付 / 已验收 / 已变更 / 已取消 | WP-NNN, WP-NNN / — | `sources/SRC-NNN` §X 第Y页 | Must / Should / Could / Won't |

## 字段说明

| 字段 | 说明 | 取值 |
|------|------|------|
| Req ID | 需求唯一编号 | REQ-[模块代号]-NNN |
| 标题 | 总览短名，通常取功能内容 | 自由文本 |
| 确认状态 | 你是否认这条需求 | 未确认 / 已确认 / 已否决 |
| 缺口 | 未确认时必填，可多项；三项没齐不得标已确认 | 做不做 / 效果未对齐 / 方案未对齐 |
| 生命周期 | 这条需求走到哪一步（不再用「已确认」占位） | 已提议 / 进行中 / 已交付 / 已验收 / 已变更 / 已取消 |
| 工作包 | 绑定的工作包，可多个 | WP-NNN, WP-NNN / —（空值进决策文件「需求未绑定工作包」） |
| 来源 | 必须能回到原件 | 文件 + 章节 + 页（如 `sources/SRC-NNN` §3.2 第12页） |
| 优先级 | 业务优先级 | Must / Should / Could / Won't |
| 属性 | 需求类型 | 功能需求 / 非功能需求 / 约束需求 / 接口需求 / 数据需求 |
| 功能域 | 一级业务域 | 如：我要注销、我要变更、开办等 |
| 功能模块 | 二级功能模块 | 如：市场主体注销、市场主体变更 |
| 功能内容 | 具体功能点 | 如：农民专业合作社公示引导 |
| 功能描述 | 需求详细描述 | 自由文本 |
| 产品负责人 | 负责该需求的产品经理 | 姓名 |
| Canonical ID | 跨源归并层指针（07 号） | CAN-NNN / 无 |
| 范围归属 | 跨源范围判定（与优先级独立） | in_contract / in_bid_only / in_initiation_only / not_in_scope / conflict |
| 是否规划 | 是否已纳入规划 | 是 / 否 / 线上不支持 |
| 评审时间 | 需求评审日期 | YYYY-MM-DD |
| 规划备注 | 规划阶段的备注 | 自由文本 |
| 关联里程碑 | 对应里程碑型工作包 | WP-NNN / — |
| 是否开发 | 是否进入开发 | 是 / 否 |
| 是否测试 | 是否进入测试 | 是 / 否 |
| 交付成果 | 交付物 | 代码 / 文档 / 接口等 |
| 验收标准 | 验收条件 | 可验证的描述 |
| 实现视图 | 面向开发的实现摘要（可选，双视图） | 关键模块/接口名 + 一句话要点（≤100 字） |
| 原型/文档链接 | 关联的原型图/设计稿/接口文档指针（可选） | 外部路径 / URL / 无（原文档不入库） |

> 旧列「关联任务」已删除，不再填写待办号。存量单元格触碰该条时改写工作包列，不批量回填待办号。
