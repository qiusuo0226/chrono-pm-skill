## 4.2 成本记哪里（Q6，V0.5 按用户纠正）

**只写在个人待办 md 里，和任务、日报同一份文件。不另开归档目录、不另开成本文件、不另开查找入口。**

查历史成本和查历史待办同一条路：打开 `todos/{日期}/{姓名}.md`。要收集一段时间，就翻那几天已经存在的个人文件。

| 那天有没有个人文件 | 成本写哪 |
|---|---|
| 有 | 就写进**那一天**那份文件的能耗段（中途补数也写回已有文件，不另存一份） |
| 没有 | **不**为补成本去新建历史空目录/空待办；把带真实日期的行写在**当前最新**那份个人文件里（仅能耗起链也是这一份） |

禁止：`todos/archive/`、`*-energy.md`、项目级成本台账、`plans/budget.md`。

**暂时性、不写日报的人：同样走个人待办能耗段，不新建项目级成本台账，不写 `plans/budget.md`。**

做法：

1. 姓名对不上花名册 → **问一次**：收编为「临时支援」并记成本 / 不收、这批跳过。禁止静默建幽灵文件。
2. 点头后：在**今天**建（或补）该人一份个人 md：§1 待办表允许空；无历史日文件的那些日期，作为带日期的行写在这一份的能耗段。花名册分配方式=`temporary`，备注=`仅能耗`。
3. **结转（已被 §4.2e 取代）**：空窗日仍建当天个人文件（待办表可空）。历史能耗投喂不单独为补数新建空日目录（有该日文件则写该日）。
4. **空闲检测（B1 C-3 + B2-1，写死）**：22 号 §3.3(1) **两个入口都删**（「曾有待办文件」**以及**「曾出现在某日 `_index` §3」），统一收敛为：**只扫「曾有 §1 待办行」的在岗人员**。
   - 仅能耗、核心表为空：即使当天出现在 §3，也不进空闲台账（FE-012）。
   - 只交过日报、从未有待办行：同样不进空闲台账。这是**有意收窄**：空闲提醒只给「派过活但现在没活」的人，不是给成本链或只交日报的人（FE-013）。
5. 对外不说章节号，说「每个人的成本消耗记在其个人待办里」。

**§1.2 与能耗段永远两路：禁止互推、禁止把工时统计材料写入预估/实际工时列。**

**单位换算（如 7.5 小时=1 人日）**：写进该项目 `project-context`「成本核算方式 / 外部填报映射」，**禁止写进 Skill 规则**。

## 4.2b 膨胀怎么做（Q7 纠正：不拆第二套文件）

V0.4 的 `todos/archive/{姓名}-energy.md` **整段撤回**。用户理由成立：那会让成本跟任务不在同一类文件里，查历史还要先判断模块类型。

膨胀靠改拷贝规则，不靠新目录：

| 规则 | 内容 |
|---|---|
| 落点 | 能耗段只存在于 `todos/{日期}/{姓名}.md`，与待办同一文件 |
| T+1 | **禁止**把历史成本日表整表拷进新一天的文件。新文件只带：① 累计数字 ② 当天一行 ③ 仍没有独立日文件的补录日期行（孤儿行） |
| 累计 | 新文件累计 = 上一份累计 + 当天量。**不含** `异常=重复待裁定` 的日。若**当天**投喂即被标重复待裁定：累计 = 上一份累计，不加当天 |
| 查询 | 问某日 → 打开该日个人文件；问一段时间 → 翻那些已存在的个人文件。与查待办历史同一路径。最新一份里的孤儿行只覆盖「从未建过文件的日期」 |
| 文件过长 | 沿用既有个人待办 300 行瘦身；不新开 doc_type、不新开目录 |
| 禁 | `todos/archive/`、energy 专档、budget、独立台账 |

这样每天的新待办不会越拷越厚；历史仍在原日文件里，和任务、日报在一起。

## 4.2c 人+日去重与异常列（Q8）

键 = **同一人 + 同一日历日**，日表只允许一行「当日能耗」。

和「分次明细」分开：

| | 分次明细 | 日表去重 |
|---|---|---|
| 什么时候 | **这一次**投喂的表里，同一人同一天有多行（一天填了好几次） | **已经记过**这一天的当日能耗，后来又投一次 |
| 怎么做 | 按人+日 SUM 成日表一行，分次表留下明细。这不是重复 | **禁止**再自动相加或覆盖。标异常，请 PM 裁定 |

**异常列**（加在能耗日表，5 列仍低于 7 列上限；不加金额列）：

`日期 | 当日能耗 | 来源 | 异常 | 备注`

取值（AI 写，PM 可改）：

| 值 | 谁写 | 何时 |
|---|---|---|
| `—` | 默认 | 正常 |
| `重复待裁定` | AI 自动 | 该人该日已有非空当日能耗，又收到一次投喂；或同一日既在「该日文件」又在「最新一份孤儿行」 |
| `量待核` | AI 自动 | 换算失败、非正数、单位对不上 project-context |
| `已裁定` | 写入 PM 裁定结果后 | 重复/量问题已经点过头；备注写裁定（覆盖 / 保留原值 / 按分次相加） |

**撞车时 AI 必须：**

1. 不改已有当日能耗数字。
2. 该行（或新候选）`异常=重复待裁定`。
3. 登记 `pm-decisions`（待确认），对外白话一次问完：
   - A. 用新值覆盖  
   - B. 留原值，丢掉新值（默认建议）  
   - C. 当成漏记的分次，把两次加起来  
   - D. 先挂着
4. **未裁定前，该日不计入累计、不参与「一共耗了多少」**（避免重复灌数把总数撑爆）。
5. 禁止静默 SUM 第二次投喂。禁止为去重去建第二套文件。

## 4.2d 补录成本怎么找（8-05 写在 8-11、8-23 再补）

旧规则（N-44 B）允许「历史日成本写在当时最新的那份个人文件里」。所以 8-05 的数可能在 8-11，不在 8-05。8-23 再补 8-05 时，只打开 8-05 会漏；全项目扫又太重。

**不落盘第二套索引。** 查找只针对**这一个人**的个人待办文件，只读能耗日表的「日期」列。

固定顺序（命中即停）：

| 步 | 打开什么 | 为什么 |
|---|---|---|
| 1 | `todos/{目标日}/{姓名}.md` 能耗段 | 新口径的家；有就最准 |
| 2 | 该人**最新**一份个人文件能耗段里「日期=目标日」的行 | 旧 T+1 整表拷贝、以及无该日文件的孤儿行 |
| 3 | 仍没有、且本轮要**写入/去重**：按文件名匹配 `todos/**/{姓名}.md`（只收这个文件名，**不把 `todos/` 一级目录当日期遍历**，避开 inbox 等）。只打开目标日之后的那些文件，只看能耗表日期列。命中即停 | 消化「补在中间某天文件里」的历史脏位置 |

禁止：扫全员、扫他项目、为查找建文件、把扫描结果落成新的索引文件。

**一次投喂很多人很多天**：每个人只编一份「日期 → 哪个文件」的**内存表**（扫该人文件一遍），用完丢掉。不要每一行都从头扫。

找到「写在别的日子的文件里」时：

- 去重仍算「已经有过」，走 §4.2c 裁定，禁止当没记过再写一条。
- 若目标日自己的个人文件存在：裁定后把这一天的成本**迁回目标日文件**（这是新口径的家），并在误放的那份文件里删掉或注明已迁，避免两处各有一行。

查询「某人某日耗了多少」同样走 1→2→3，不换入口。

**同一次表内**多人多日：每人每天先 SUM 成一行再写入；只对「库里已经有这一天」的人走裁定，不要对整张表逐行都问。

# 12. 风险与边界 / 兼容

- 只读契约：集层日志可写 `portfolio/logs/`；成员日志按管理路径推导，**不加指针列**；成员 ai 零写。
- 旧 ops 文件：整文件冻结只读，不追加；与 §6.1b 相同。不回写 08-22 垃圾行。
- 3.8.0「不灌 xls」= 那一版不代迁业务数据，本轮 Skill **允许**按 N-44 入库；本轮执行仍**不**给市监灌数。
- 对话日志不是事实源，不能当进度。
- 不得记录密码/API Token；token 列仅用量数字。

## 12.5 方案影响与必要性

| 影响维度 | 是否 | 说明 | 程度 |

历史体验：增强（今天能看到今天的对话；投喂不再石沉大海）。削弱：旧「未知」行不再当合格日志；查 token 若宿主不给就没有（本就没有）。兼容：目录仍 `logs/ops/` 与 `portfolio/logs/`。

A 意见：**支持**，范围收敛为 R1+R2。砍掉：独立成本台账、V-13、写死列名、本轮灌市监数据。
