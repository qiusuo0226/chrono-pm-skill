## Change Goal

> 可验证目标：

1. 05号 §6.7 新增"倒排每日矩阵"查询视图：PM 查询时输出人员×日期矩阵（行=Owner，列=工作日，格=Task 简述），支持 portfolio 多 board 遍历和 single 模式。
2. 存量工作区兼容：无 iteration-register 或无 WP Ref 列时，矩阵仍可生成（降级策略）。
3. WF-7 草案输出规范：草案行补充读文件列 + 倒排每日矩阵输出 + 两阶段数据源区分（初始草案=WBS 产出 / 刷新=board 派生）+ WF-8 闭环。
4. 10号追加查询附带提示：board 变更后查询倒排内容时附带"建议刷新"提示。
5. 存量工作区零迁移：schema 保持 0.8.0，旧工作区不受影响。

## Problem Statement

当前问题：

1. **WF-7 倒排计划无法按人按天跟踪**：倒排计划的"每日排期草案"按"角色大类×日期"组织（产品/开发/测试/里程碑四列），无法看到"每个人"每天需要做什么，无法按天跟踪。
2. **草案内容更新滞后**：PM 已口述"王涛周二要做XX"，但每日排期草案里还只显示旧内容。根因是草案文件（dev-freeze-plan.md）与 board 无派生关系，是游离文件。
3. **草案阶段无模板约束**：WF-7 草案行读文件列为"—"，输出无格式规范，AI 自由发挥导致格式不一致。

## 升级方案审查文档（AP）

### AP-1. 变更概述

在 WF-7 倒排计划编排中新增"倒排每日矩阵"查询视图（人员×日期），解决 PM 无法按人按天跟踪倒排进度、以及草案内容更新滞后的问题。改动范围：3 个规则文件追加（05号/00号/10号）+ 回归 Module 38 + 元数据同步。0 新增文件、0 schema 变更。00号修改触发 contract_change，需全量回归。

### AP-2. 影响点详细分析

| 影响项 | 当前状态 | 变更后状态 | 影响描述 | 影响程度 | 是否可逆 |
|---|---|---|---|---|---|
| 05号 §6.7 | 6 种查询路由 | 7 种（+倒排每日矩阵） | 新增查询行 + 视图规格 + 降级策略 | low | 是 |
| 00号 WF-7 | 草案行读文件="—" | 读文件=board+iteration-register | 草案输出含矩阵 + 两阶段数据源 | medium | 是 |
| 10号 §2 L3 | 倒排信号无查询提示 | 追加查询附带提示 | 不新增触发类型 | low | 是 |
| 回归套件 | 259 用例 / 37 模块 | 269 用例 / 38 模块 | +Module 38（BDM-001~010） | low | 是 |

### AP-3. 变更策略与设计思路

1. 为什么选择这个方案：扩展现有查询能力（05号 §6.7），不新增文件/模板/模块，最小化维护点
2. 设计思路：board 唯一事实源 + 派生视图原则；矩阵为查询时实时生成（query-time derivation），自动解决 stale data
3. 关键决策点：数据源多 board 遍历（portfolio 兼容）、存量降级策略、初始草案/刷新区分两数据源、contract_change 确认触发、C-03 保鲜降级为查询附带提示
4. 与现有规则的交互：与"倒排倒计时"行两文件读模式一致；与 WF-8 口述→board 链路闭环
5. 替代方案（已否决）：新增独立倒排计划模板——违反"board 唯一事实源 + 派生视图"原则
