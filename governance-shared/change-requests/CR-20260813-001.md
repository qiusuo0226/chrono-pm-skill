## Change Goal

为 ChronoPM 新增"跨源需求归集与判定（Requirement Intelligence, RI）"能力：在现有需求登记册（07 号）基础上，建立"ATOM（证据）→ Canonical（归并）→ REQ（管理）"三层数据模型，对合同/招投标/立项/密评/里程碑等**多来源文档**做 AI 拆词、语义归一、跨源合并与范围判定（scope_scope），满足"某需求是否在合同/招投标/立项范围内"的取证与检索，并解决大文档可维护性与 AI 检索不全问题。可验证目标：1) 新增需求可提取为 ATOM 并归并为 Canonical；2) 可回答范围归属并给出证据链；3) 三级索引使单次范围判定查询满足最小读取（≤400 行）；4) 随笔支持"AI 主动感知 + PM 主动要求"双入口。

## Problem Statement

当前问题：大型 To G/To B 项目中，客户/内部常就"需求在不在合同、招投标、立项范围内"扯皮。需求分散在多个权威文档，无统一可追溯、可检索、可判定的证据链；大文档存原文不可读；相同需求在不同文档表述不同，Ctrl+F 无法命中；PM 的方法论/干系人洞察无低结构化存储位易丢失。

## Acceptance Criteria

1. 新增规则章节可在 PM 提供源文档后提取 ATOM 并归并为 Canonical，给出 scope_scope 与证据链。
2. 三级索引（L1 路由 / L2 类别倒排含 norm_text 摘要 / L3 全文）+ 分级加载使单次范围判定 ≤400 行。
3. P1 语义兜底（词库同义词扩展 / norm_text 扫读 / 降级提示）覆盖非同义词近义检索。
4. source_type 项目级可扩展：新文档类型仅需 source-type-registry 登记，不改规则文件。
5. workspace schema 升级 0.7.0，迁移脚本可创建单人/项目集模式目录；旧工作区迁移不丢数据。
6. project-notes 支持 AI 主动感知 + PM 主动要求双入口，属低/中风险追加写入。

## 升级方案审查文档（AP）

> 本 CR 方案源自四次 A/B 迭代（V0.1→V0.4）。V0.4 经 B 终审 A 通过，16/16 需求闭环。完整方案见 `governance/planning/requirements-intelligence-scheme.md`。

### AP-1. 变更概述

在 07 号需求规则上扩展"跨源需求归集"能力：三层数据模型 + 双层源分类 + 三级索引 + P1 语义兜底 + 随笔双入口，workspace schema 升级 0.7.0。

### AP-2. 影响点详细分析

| 影响项 | 当前状态 | 变更后状态 | 影响描述 | 影响程度 | 是否可逆 |
|---|---|---|---|---|---|
| workspace schema | 0.6.0 | 0.7.0 | 新增 canonical/atoms/registry 目录 | 高 | 可迁移 |
| 07 号需求规则 | 需求登记册+追踪矩阵 | 增跨源章节 | 新增 ATOM/Canonical/范围判定 | 中 | 可回滚 |
| REQ 来源字段 | 自由文本 | 指向 Canonical ID（向后兼容） | 指针化 | 低 | 可逆 |
| 目录结构 | requirements/ 两文件 | 增 6 类 category + L1/L2/L3 索引 | AI 读取路径变化 | 中 | 可迁移 |

### AP-3. 变更策略与设计思路

1. 为什么选择这个方案：扩展现有 07/17/05 规则而非另起炉灶，复用词库/查询/目录既有机制，符合"防臃肿"约束。
2. 设计思路：证据(A)、归并(Canonical)、管理(REQ)三层解耦，双层源分类解耦权威性与可扩展性，三级索引解耦精度与效率。
3. 关键决策点：scope_scope 归 Canonical 层；L5 归属 operational；P1 用 Markdown 索引 + 语义兜底而非向量库。
4. 与现有规则交互：17 号复用归一，05 号复用查询与最小读取，06 号复用目录/归档，16 号治理，18 号初始化向导。
5. 替代方案对比（被否决）：(a) 独立向量库方案——引入重型依赖，违背 Markdown 事实源理念，否定；(b) 另起独立需求模块——与 07 号重叠致数据割裂，否定。
