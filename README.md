# ChronoPM v1.16.3

**让 AI 帮你管项目，而不是帮你写文档。**

## 这是什么？

ChronoPM 是一个给项目经理用的 AI 技能（Skill）。装上之后，AI 就能理解你的项目，帮你处理日常管理工作——写日报、整理会议纪要、跟踪任务和风险、管理需求变更、生成周报月报。

它不是又一个项目管理软件。它直接在你现有的文件夹里工作，所有项目数据都是 Markdown 文件，不依赖任何数据库或云服务。

**简单来说：它就是一个越用越懂你项目的 AI 助手，把散落的项目信息自动整理成体系化的知识资产。**

## 这些痛点，你遇到过吗？

做项目管理的人，大概对以下场景都不陌生：

**1. 管理标准不统一**
不同项目经理的管理习惯和方法不一致。同一个项目，换一个人来管，成本把控、风险识别、干系人管理的颗粒度完全不一样。这不是能力问题，而是缺乏一套统一的框架来兜底——项目质量过度依赖个人经验。

**2. 日常琐碎导致信息断层**
项目经理即使建立了比较完备的管理机制和文件体系，但因为日常琐碎事务太多，经常出现某项关联文件没有及时同步的情况。看似小事，但信息一旦断链，累积起来就是项目风险。

**3. 项目交接质量不可控**
项目经理是流动的，人员变动时交接往往不到位。以前的做法是甩一份项目文档包，但几十上百个文件，接手的人根本不知道从哪里看起、哪些是关键信息。隐性风险在交接中埋下，等爆发时已经来不及了。

**4. 大量时间花在文档整理上**
周报、日报、会议纪要、风险清单、变更申请……每天花大量时间整理文档，反而挤压了真正应该花在沟通协调上的精力，本末倒置了。

**5. 验收报告缺乏系统性支撑**
最终的项目验收报告，内容来源于日常管理过程中产生的各种材料。但这些材料分散在各个文件、各个系统里，即使想用 AI 来辅助整理，从零开始投喂也耗费大量精力，而且因为没有完整的投喂标准，效果往往不理想。

**6. 通用 AI 工具不理解项目语境**
项目有大量的专属名词、缩写、内部代号。用通用 AI 的话，需要不断重复解释背景，资源消耗巨大还达不到满意效果，最后大家还是觉得不如自己干。

**7. 多项目联动缺乏全局视角**
高级项目管理者同时管多个项目，需要跨项目统筹资源、了解各项目进度之间的关联影响。但目前没有一个工具能把这些分散的信息串联起来，形成全局视图。

## ChronoPM 怎么解决？

ChronoPM 的定位是**项目管理智能知识助手**。靠日常工作中项目经理持续"投喂"项目相关材料——会议纪要、需求文档、风险清单、周报日报、沟通记录等等——它会自动理解项目专属语境，从成本、资源、干系人、风险、问题、进度等多个维度，生成结构化的项目知识索引，最终形成一套**可读取、可传递、可复用的项目知识包**。

## 带来什么价值？

**拉齐管理基线——给每个 PM 配一个"虚拟 PMO"**
不管项目经理经验深浅，工具都从统一的维度框架去补全信息，不会因为个人习惯不同而遗漏关键维度。管理质量有了下限保障。

**交接从"人走茶凉"变成"知识带走"**
项目交接时，只需移交这套结构化索引文件夹。接手人直接让 AI 读取，快速理解项目全貌——成本花了多少、哪些风险还没关闭、干系人诉求是什么、遗留问题清单。不需要再一个个翻文件，交接质量不再依赖个人表达能力。

**日常材料自动沉淀，释放 PM 精力**
周报、日报、会议纪要投喂进去后，工具自动结构化归档。项目经理不用花大量时间整理文档，把精力还给沟通和协调。同时，这些日常沉淀直接为最终验收报告提供系统性支撑——验收不再是"临时拼凑"，而是"水到渠成"。

**理解项目专属语境，越用越准**
通过持续投喂建立项目专属的知识索引，项目名词、内部代号、历史上下文都能被准确理解。不需要每次重复解释背景，彻底解决通用 AI"听不懂项目话"的问题。

**多项目联动，形成全局视图**
高级项目管理者可以通过关联多个项目的知识包，跨项目统筹资源、对比进度、识别资源冲突，辅助决策。

**零额外学习成本**
它不是一个新系统、新平台，不需要改变现有工作习惯。项目经理只需要像平时一样把材料丢给它，它自动完成结构化整理。

## 怎么用？

**第一步：安装 Skill**

把本目录复制到你的 AI 工具（如 Qoder）的 Skill 目录下即可。

**第二步：初始化工作区**

告诉 AI："帮我初始化项目工作区"。AI 会引导你一步步建立项目结构——项目名称、有哪些人、什么阶段、用什么模式。

**第三步：日常使用**

像跟助手说话一样跟 AI 交流：

| 你说 | AI 做 |
|---|---|
| "今天的日报" | 汇总今天所有更新，生成日报，联动更新个人进度 |
| "开个项目启动会，要点如下…" | 整理会议纪要，提取待办事项，分配到责任人 |
| "客户要加一个 XX 需求" | 登记需求，评估影响范围，更新追踪矩阵 |
| "这周进展怎么样" | 从各文件汇总生成本周周报 |
| "项目集整体状态" | 汇总各子项目状态，生成项目集月报 |
| "检查一下项目信息完不完整" | 扫描所有管理文件，列出缺失项并分级提醒 |
| "这个需求在不在合同范围内" | 从合同→招投标→具体需求三层追溯，给出证据链 |

## 两种工作模式

- **单项目模式**：一个 `ai/` 文件夹管一个项目，适合独立项目。
- **项目集模式**：一个项目集管多个子项目，信息自下而上汇总、决策自上而下通知。适合管一组相关项目的 PM。

## 核心特点

**Markdown 文件就是数据库**
所有项目信息都存在 `.md` 文件里。不依赖任何软件、数据库或云服务。用文本编辑器就能打开看，十年后还能读。

**AI 先读后写，人工确认才生效**
AI 每次操作前先读取现有文件了解上下文。写入重要信息前会先让你确认，不会自作主张改掉你的数据。

**改了什么一目了然**
需求登记、变更控制、影响分析——每一步都有记录。谁提的、什么时候、影响了哪些文件，全部可追溯。

**项目知识不随人员流动**
所有项目知识都在文件里。新人来了，AI 读完文件就能接手；人走了，项目历史不会丢。

**从日报到月报一条龙**
日报、周报、月报、会议纪要、决策记录、复盘总结——全部有标准模板，AI 自动填充和汇总。

**需求范围可追溯**
从合同到招投标文件到具体需求，三层模型帮你搞清楚"这个需求在不在合同范围内"。
