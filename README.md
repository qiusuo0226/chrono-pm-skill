# ChronoPM v1.16.2

**让 AI 帮你管项目，而不是帮你写文档。**

## 这是什么？

ChronoPM 是一个给项目经理用的 AI 技能（Skill）。装上之后，AI 就能理解你的项目，帮你处理日常管理工作——写日报、整理会议纪要、跟踪任务和风险、管理需求变更、生成周报月报。

它不是又一个项目管理软件。它直接在你现有的文件夹里工作，所有项目数据都是 Markdown 文件，不依赖任何数据库或云服务。

## 解决什么问题？

做项目管理的人大概都经历过这些：

- **信息散落在各处**——日报在群里、任务在 Excel 里、需求在 Word 里、决策在脑子里。想找某个东西，翻半天找不到。
- **AI 不懂你的项目**——你问 AI 帮忙写个日报，它写出来的东西跟你项目毫无关系，因为它不知道你的项目有哪些人、在做什么、什么进度。
- **变更不受控**——客户说改就改，改了什么、影响了什么、谁同意了谁没同意，事后一笔糊涂账。
- **交接就断档**——人一换，项目历史就丢了。

ChronoPM 用一套 Markdown 文件把所有项目信息组织起来，AI 读完这些文件就了解你的项目全貌，然后帮你干活。

## 怎么用？

**第一步：安装 Skill**

把本目录复制到你的 AI 工具（如 Qoder）的 Skill 目录下即可。

**第二步：初始化工作区**

告诉 AI："帮我初始化项目工作区"。AI 会引导你一步步建立项目结构——项目名称、有哪些人、什么阶段、用什么模式。

**第三步：日常使用**

像跟助手说话一样跟 AI 交流：

| 你说 | AI 做 |
|---|---|
| "今天的日报" | 汇总今天所有更新，生成日报，联动更新个人进度 |
| "开个项目启动会，要点如下…" | 整理会议纪要，提取待办事项，分配到责任人 |
| "客户要加一个 XX 需求" | 登记需求，评估影响范围，更新追踪矩阵 |
| "这周进展怎么样" | 从各文件汇总生成本周周报 |
| "项目集整体状态" | 汇总各子项目状态，生成项目集月报 |
| "检查一下项目信息完不完整" | 扫描所有管理文件，列出缺失项并分级提醒 |

## 两种工作模式

- **单项目模式**：一个 `ai/` 文件夹管一个项目，适合独立项目。
- **项目集模式**：一个项目集管多个子项目，信息自下而上汇总、决策自上而下通知。适合管一组相关项目的 PM。

## 核心特点

**Markdown 文件就是数据库**
所有项目信息都存在 `.md` 文件里。不依赖任何软件、数据库或云服务。用文本编辑器就能打开看，十年后还能读。

**AI 先读后写，人工确认才生效**
AI 每次操作前先读取现有文件了解上下文。写入重要信息前会先让你确认，不会自作主张改掉你的数据。

**改了什么一目了然**
需求登记、变更控制、影响分析——每一步都有记录。谁提的、什么时候、影响了哪些文件，全部可追溯。

**项目知识不随人员流动**
所有项目知识都在文件里。新人来了，AI 读完文件就能接手；人走了，项目历史不会丢。

**从日报到月报一条龙**
日报、周报、月报、会议纪要、决策记录、复盘总结——全部有标准模板，AI 自动填充和汇总。

**需求范围可追溯**
从合同到招投标文件到具体需求，三层模型帮你搞清楚"这个需求在不在合同范围内"。

## 目录结构

```
ChronoPM Skill/
├── SKILL.md           # AI 入口——AI 读这个文件知道该怎么帮你
├── skill.json         # 版本与元数据
├── VERSION            # 当前版本号
├── CHANGELOG.md       # 变更历史
├── references/        # 22 份规则文件（AI 的行为准则）
├── assets/templates/  # 48 个文档模板
├── scripts/           # 自动化脚本
├── governance/        # 治理契约与变更管理（开发者使用）
└── tests/             # 回归测试套件
```
