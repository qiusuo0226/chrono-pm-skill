# ChronoPM v3.25.2 — 会管项目的 AI 副手

**你负责判断，它负责记、算、盯。项目的一切事实写在 Markdown 里，跟着项目走。**

ChronoPM 是一套装进 AI 助手的项目管理方法论：你照常说话——丢一份日报、贴一段纪要、问一句进度——它把项目事实沉淀到一套干净的 Markdown 文件里；要紧的变更先问过你再生效。人走了、AI 工具换了，项目记忆都留在文件夹里。

> **双包分工**：日常录入用 **ChronoPM-Project**（单项目，所有写动作只发生在这里）；跨项目的进度 / 风险 / 合同 / 周报汇总用 **ChronoPM-Portfolio**（只读，绝不反向修改成员项目）。
>
> **Python**：初始化 / 升级 / 巡检脚本需要 Python **≥3.9**（推荐 3.10+）。日常记待办、查进度不依赖 Python。

## 为什么需要它

PM 的项目事实总是散落各处：日报在群里，纪要在邮箱，风险在某个人脑子里，进度在一份过时的 PPT 里。想确认"这个需求当初是怎么定的"，往往要考古半天。

通用 AI 帮不上太多忙：上下文一断就忘了你的项目；一句随口说的"这里好像有风险"，它会热情地登记成正式风险条目；给出的数字没有来源，你也不敢直接用。

交接更难：打包十个文件夹发过去，接手的人对着陌生的结构从零摸索。

ChronoPM 把这三件事一起解决：**事实写在文件里，AI 守着文件，你把关变更。**

## 三个约定

整个体系只建立在三个约定上，其余能力都是它们的延伸：

1. **事实只存一份。** 待办、风险、问题、决策、需求、合同各有唯一的事实源文件；日报、周报、进度、倒排计划全部从事实源实时派生。没有第二份真相，也就不存在"对不上"。
2. **AI 先动笔，你后点头。** 你说话时提到新需求、新风险、人员变化，AI 会主动接住并整理登记；但完成、关闭、删除这类改变事实的操作，必须经过你的确认才生效，每一次变更都留痕可查。
3. **交接就是递一个文件夹。** 所有管理动作都发生在项目自己的 `ai/` 目录里，不碰业务交付物。接手的人把 `ai/` 交给 AI，读完就能接上。

## 开口就能用

| 你说 | 它做 |
|---|---|
| 「今天的日报……」 | 归档存底、更新责任人待办、发现风险苗头先出判定卡，你确认才登记 |
| 「纪要如下……」 | 落成结构化会议纪要，行动项拆到责任人名下 |
| 「把这份规格拆文件」 | 拆进 `ai/requirements/sources/`，不是只出 HTML |
| 「安排苏晚测登录和登出」 | 先查重，主题可分则拆成两条待办，各绑一个工作包 |
| 「这周进展怎么样」 | 从待办实时汇总周报，每个数字可回溯 |
| 「下个月要上线，倒排一下」 | 从里程碑反推计划，标出关键路径与资源冲突 |
| 「项目集整体状态怎么样」 | 换 ChronoPM-Portfolio 只读归集多个项目，给出总览 |
| 「这计划谁还没排」 | 打开计划看节点子行，空岗标待安排人/待排期 |
| 「归纳各项目 10 月 7 号前的计划」 | 不按计划名，按时间窗叠各项目正常计划里的工作包 |
| 「这是 skill 的问题，记成升级需求」 | 在 `ai/outputs/` 落一份技能缺口说明，不写进项目需求册 |

日常管理的完整面都在覆盖范围里：需求与变更追踪、待办与工作包、计划与倒排、里程碑、风险与问题、决策记录、会议与评审、日报周报、人工成本台账、经验教训，还有一个随项目生长的词库——让 AI 越来越听得懂你的项目黑话。

## 快速开始

1. 把 `ChronoPM-Project/`（需要跨项目汇总就再加 `ChronoPM-Portfolio/`）复制到 AI 工具的技能目录。不要复制整个仓库根目录。
2. 对 AI 说：「帮我初始化项目工作区」。
3. 之后像跟助手说话一样，把材料丢给它。

从源码仓库打包：`python tools/pack-skill/scripts/pack.py --skill-root ChronoPM-Project`  
发布前：`python governance-shared/scripts/audit_release.py` 必须通过。

```
├── README.en.md
└── LICENSE.txt
```
