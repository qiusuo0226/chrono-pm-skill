# ChronoPM v3.8.0 — ChronoPM-Project 单项目 + ChronoPM-Portfolio 只读集

**让 AI 帮你管项目，而不是帮你写文档。**

装上 Skill，把日报、纪要、合同丢给 AI。事实写在 Markdown 里，确认后才生效。人走知识留在文件夹里。

> **双包**：日常录入用 **ChronoPM-Project**。跨项目进度 / 风险 / 合同 / 周报用 **ChronoPM-Portfolio**（只读，不写成员项目）。

## 全局概念

先记住这几条，后面所有能力都围着它们转。

| 概念 | 一句话 |
|---|---|
| 写归 Project，读归 Portfolio | 事实只写进本项目 `ai/`。跨项目只汇总、不改成员项目。 |
| 待办是最小事实 | 执行状态只在 `todos/{日期}/{人}.md`。日报、周报、进度都是从它派生，不是第二份真相。 |
| 人点头才算数 | 完成/关闭/删除/跨项目写入，要你确认。AI 可以先写待确认，不能替你改已生效事实。 |
| 花名册不是新文件 | 全员名单就是当天（或最新合法日）`todos/{日期}/_index.md` 的 §1。禁止再维护一份人员登记册。 |
| 人的身份分三层 | 岗位/在组状态在花名册；联系方式在个人 §0；进出组在个人 §0.5。成本/能耗在个人 **最新文件** 的 §0.6，新文件整表拷贝再追加，不建历史空目录。 |
| 单位由项目自己定 | 人日、人时、人月都由 `project-context`「成本核算方式」登记。Skill 不写死某一家的算法。 |
| 归档 ≠ 备份 | 归档是还要查的活历史，按索引读。`backup/` 是升级垃圾，默认不读。 |
| 明日不是明天的目录 | 日报里的「明日」写进**今天**的待办。禁止提前建未来日期文件夹。 |

## 你可能正在这样耗时间

| 痛点 | ChronoPM 怎么接 |
|---|---|
| 换个 PM，标准全变 | 统一规则兜底，不靠个人习惯 |
| 日报、风险、待办对不上 | 待办文件是唯一事实源，报表都是派生 |
| 交接甩一包文件，接手找不到北 | 移交 `ai/` 文件夹，AI 读完就能接 |
| 通用 AI 听不懂项目黑话 | 词库 + 项目记忆，越用越准 |
| 「有风险」四个字就被登进登记册 | v3.7.0 判定卡：先三问，确认才写 |

## 开口就能用

| 你说 | AI 做 |
|---|---|
| 「今天的日报」 | 存档、映射待办、该问的风险先出判定卡 |
| 「纪要点如下…」 | 纪要 + 行动项落到责任人待办 |
| 「这个需求在不在合同里」 | 合同 → 招投标 → 条款，带证据链 |
| 「这周进展怎么样」 | 从待办汇聚周报，不编造 |
| 「跨项目整体状态」 | 换 ChronoPM-Portfolio 只读归集 |

**写只写待办文件** `todos/{日期}/{人}.md`。日报/周报/进度/倒排都从它实时汇总。任务包 `WP-NNN` 管分组和里程碑；进度 = 下辖待办完成比例，不另存一份过时数字。

终态（完成/关闭）要你确认。AI 不替你改事实。

## v3.8.0 这一版多了什么

- **人员只走待办**：`resource-register` / `transfer-log` 退役。花名册在 `_index` §1，进出组在个人 §0.5。
- **确认说人话**：对外不问路径、编号、工序名；「请你确认」只表示认不认或准不准。
- **禁止提前建明天的待办目录**；改一个人的待办前，先按花名册把该建的人结转完。
- **人工成本台账**：§0.6 按天累积；没填核算方式时，你提到人工成本也可以记；和公司系统对账由你负责。
- **项目集**：V-11 共享文件拆分建议、V-12 术语指针索引（只读）。

## 两种用法

- **单项目**：一个 `ai/` 管一个项目。
- **项目集**：Portfolio 只读汇总多个项目；跨项目数字查询时现算，不落盘。

## 装上就能跑

1. 把 `ChronoPM-Project/`（跨项目再加 `ChronoPM-Portfolio/`）复制到 AI 工具的 Skill 目录。不要复制整个仓库根。
2. 对 AI 说：「帮我初始化项目工作区」。
3. 日常把材料丢给它，像跟助手说话。

开发仓打包：`python tools/pack-skill/scripts/pack.py --skill-root ChronoPM-Project`  
发布前：`python governance-shared/scripts/audit_release.py` 必须通过。
