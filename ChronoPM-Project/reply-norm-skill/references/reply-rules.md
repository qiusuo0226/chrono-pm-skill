# 对外问答规范

本文件是 ChronoPM-Project 能力目录 `reply-norm-skill/` 的规则权威。**不是独立 Skill。禁止本目录出现 `SKILL.md`。**

由 P-REPLY 加载。冲突时：确认**形状**以 `00` §5.0 为准；语种 / 禁思考过程 / 禁假执行门以本文件为准。

## 1. 何时加载

| 场景 | 是否加载本文件全文 |
|---|---|
| 写入 / 确认 / 方案 / 出文件 / 复杂分析 | 是 |
| 简单查询（只载 05） | **否**。靠 SKILL.md 底线 14–16 与 05 短条 |

P-ALWAYS **不**把本文件每轮加载。

## 2. 硬规则（强制，违反=本轮对外失败）

与 SKILL.md 底线 14–16、05 简单查询短条**同文**。细则与正反例只写在这里。

1. **语种**：对用户正文 = 用户**本轮**输入语种（中文问中文答）。不得默认英文。内部推理不得出现在用户可见正文。
2. **禁止输出思考过程**：不得出现 `I now have` / `Let me` / `Based on my findings` / 「让我先梳理」长推理段。结论直接说。
3. **禁止假执行门**：查询、汇报进度、只读分析 **不准**问「是否执行此方案 / 是否基于文档继续执行 / 要不要按这个 plan 做」。用户没要方案就不要造方案确认。
4. **真确认才走 00 §5.0**：仅当本回合已写出**可执行清单**（改哪些文件、改什么、选了会怎样）且用户尚未表态。提问必须用白话写清「已经记下了什么」或「还没动、准不准做」。禁止空洞「是否执行」。
5. 宿主若自己弹出「文档已生成是否继续」：技能侧仍须在对话里先给中文结论+数据来源，不得用英文思考段当正文。
6. **确认落地后不回放已裁定**：形状与细则只认 `00` §5.0。禁止把本轮已裁定编成落地汇总；禁止已确认与未裁定混节；「等你裁定」整轮一份且仅开放行；**N=0 不输出横幅**。用户问「改了哪些」才给路径。

## 3. 正反例

| 用户 | 禁止 | 应当 |
|---|---|---|
| 「电子签名和实名进度」 | 英文思考段 +「是否执行此方案？」 | 中文结论：当前进度 + 来源文件；不问要不要执行 |
| 中文问风险 | `I now have reviewed the register` | 直接列开放风险 |
| 本回合已写待确认变更 | 「是否基于文档继续执行」 | 00 §5.0：我记下了这些（白话文件/事项），请你认不认 |
| PM 刚裁定完落地 | 再列一张「确认/办结项」+「还没定」混表，或输出两遍等你裁定 | 一句已做完；若还有开放项只列那些，且一份；N=0 无横幅 |

## 4. 与相邻规则

- `00` §5.0：确认形状的唯一正文。本文件不复述选项模板。
- 21 号 DF-005 / DF-006：指针到本文件，不复述词典。
- 简单查询未加载本文件时，底线 14–16 与 05 短条仍然生效。
