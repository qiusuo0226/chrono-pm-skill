# 22 待办结转规则（v2.1.0 新增）

## 1. 定位与边界

### 1.1 定位

本规则定义待办结转（carryover）完整机制：AI 为某个日期创建/更新待办文件前，必须先扫描未办结待办（及能耗链）并结转到当日，保证未办结任务与人员能耗不因日期切换而丢失。

- 本规则是 `00-pm-main-rules.md` §4c（硬阻断要点）与 WF-8 Step 0 的完整机制承载，AI 执行结转时按需读取本文件
- 结转标记落点：`todos/{date}/_index.md` §2（模板见 `assets/templates/daily-todo-binding-template.md`）
- 结转条目落点：`todos/{date}/{姓名}.md`（模板见 `assets/templates/personal-daily-todo-template.md`）

### 1.2 边界

- 结转只搬运未办结待办（状态 ≠ 已完成/已取消/已转出），不改写原文件历史条目
- 结转不产生新编号（同人结转编号不变，见 §5 编号硬约束）
- 结转不得修改待办的 WP Ref / 计划 Ref 归属
- 本规则不覆盖"换人（转交）"场景的重新分配决策（转交需 PM 指示，见 §5 场景对比）
- T+1 拷贝范围含 §0 / **§0.5 进出组记录** / **§0.6 能耗记录**（N-44 B：从该人最新文件整表拷贝 §0.6 再追加当日行）
- 空窗日（无未办结且无今日能耗投喂）不生成占位文件；滚存源 = 该人最新存在的文件
- 扫描名单 = 最新合法 `_index.md` §1 花名册（date≤今天）；扫描排除 `archive/` 与 `backup/`
- 本包不代写他项目结转（见 Step 0.5）
- 禁止创建 `todos/{date>今天}/`；休息日无人上班不建目录（N-37 / N-38）
- 禁止为历史回填建空目录；仅今天的能耗投喂才起链（N-44 B）

## 2. 触发时机（3 时机）

| 时机 | 触发条件 | 动作 |
|---|---|---|
| 时机 0（N-43 创建契机） | 本次操作触及 `todos/{今天}/{任何人}.md` 或今天 `_index.md` | 按下述 if-else。未操作个人待办类文件则不触发 |
| 起链扩展 | 有未办结待办 **或** 当日有能耗投喂 | 满足任一即纳入结转/生成对象。空窗日不生成占位文件。**N-44 B**：仅「今天」的能耗投喂才起链；历史日投喂不建目录 |
| 时机 1（状态表读取） | AI 开始为日期 D 创建/更新任何待办文件时（时机 0 未跳过） | 读取最近合法日 `_index.md` §2.3 每人独立结转状态表，逐行解析并输出"状态表读取确认"；缺失/格式错误按 §6 错误处理 |
| 时机 2（标记更新） | AI 完成所有人的结转操作后、写入任何新待办前 | 再次读取 §2.3 对比时机 1 快照，确认无并发修改后被修改则重新从时机 1 开始；未变则按 §4 顺序更新标记 |

### 2.1 时机 0 if-else（N-43）

```
IF 本次操作触及 todos/{今天}/{任何人}.md  或  今天的 _index.md：
    IF 目标日期 > 工作日历的「今天」：
        拒绝创建/写入该日期目录（N-37）
        把内容落到合法当天文件（日报「明日」进当天 §2）
    ELSE IF 今天 _index.md 不存在
         OR carryover_done_for_today 不是恰好 true
            （缺省、false、「部分」等非法值一律 = 未完成）：
        先做 Step 0（全员，扫描名单 = 最新合法日 `_index` §1，date≤今天）
            该起链的人：有未办结待办 / 当日有日报或能耗投喂 / 当天被点名操作
                → 建或补个人 md + 写入新 §3
            不起链的人：从未派活编制、已出组、空闲且无未办结
                → 只留在 §1，不建空文件
        写 carryover_done_for_today=true（成功或「失败留待明日」都算本次 Step 0 做完）
        再检查：index 在、标记恰好是 true
        THEN 才改点名的那个人
    ELSE：
        今天结转已完成 → 直接改点名的那个人（可追加到已有文件）
ELSE：
    没操作个人待办类文件 → 不触发（查进度、出周报等不因此建目录）
```

禁止只给日报点到的几个人建残缺当天目录。`carryover_done_for_today=部分` 视为没完成。

## 3. Step 0 执行流程（增强算法）

**扫描名单**：最新合法 `_index.md` **§1 花名册**（`date≤今天` 且存在 `_index.md` 的最大日期）。`date>今天` 的目录视为非法，不参与最新判定、不进扫描名单。扫描待办目录时排除 `archive/` 与 `backup/`。当天 `_index` §1 从上一合法日拷贝全员；§3 只记当天实际有文件的人。

1. **日级完成检查**（时机 0 / N-43）：今天 `_index.md` 存在且 `carryover_done_for_today` **恰好**为 `true` → 跳过 Step 0。缺失 / false / 「部分」等 = 未完成
2. **读取最新合法日** `_index.md`（不必是日历昨天）
3. **快速路径检查（历史）**：若该 index 的 `carryover_traced_until` = 其自身日期 → 所有人历史已确认，只需扫描该日；否则按每人独立状态确定扫描范围
4. **确定每个人的扫描范围（每人独立）**：
   - 状态 = `已确认`，最后确认日期 = D → 该人扫描范围 = D+1 到 `date-1`
   - 状态 = `待处理` 或 `失败` → 扫描范围 = `date-7` 到 `date-1`（回溯 7 天）
   - 不在状态表中（首次出现）→ 扫描范围 = `date-7` 到 `date-1`
   - 昨天 `_index.md` 不存在 → 从 `date-1` 向前找最近合法 `_index.md`（最多 7 天，跳过无目录的休息日）：找到按其状态表定范围；找不到则全员扫描范围 = `date-7` 到 `date-1`，并输出「⚠️ 最近 7 天无待办记录，无法执行结转检查，本次仅创建新待办」后继续
5. **逐日逐人扫描**（扫描范围内从早到晚；名单=最新合法 §1，不是残缺的当天 §3）：
   - 该天 `_index.md` 存在且该人在 §1 花名册：
     - 当天有待办文件 → 筛选状态 ≠ 已完成/已取消/已转出 的待办，有则在 `todos/{date}/{姓名}.md` 创建结转条目
     - 当天无待办文件（AI 漏建/请假）→ 从该天向前追溯最多 7 天找该人最近待办文件：找到则扫描未办结并结转；找不到则状态 = `失败`，备注「7 天内无待办文件」
   - 该天 `_index.md` 不存在（休息日无人上班）→ 跳过该天，不建目录（N-38）
6. **更新追溯标记**（每人独立）：
   - 结转成功 → 该人"最后确认日期" = `date-1`，状态 = `已确认`
   - 结转失败 → 状态 = `失败`，记录警告，不影响其他人
   - 全局标记：**所有人员**状态都为 `已确认` 时才更新 `carryover_traced_until` = `date-1`；任何人为 `失败`/`待处理` 则不更新
7. **输出结转报告**：每人扫描范围 + 结转了哪些人的哪些待办 + 失败/警告 + 更新后的每人状态表
8. **写入日级完成标记**：在 `todos/{date}/_index.md` 设置 `carryover_done_for_today=true`

> **语义澄清**：`carryover_done_for_today=true` 表示"今天的 Step 0 已执行完毕"，**不等于"所有人都成功结转"**。若某人状态为"失败/待处理"，日级标记仍为 `true`（今天不再重试），失败留待**明日 Step 0 再处理**。状态机中"失败→已确认"是跨天转换，AI 不得因日级标记=true 而误判为全员成功。

> **硬阻断**：Step 0 未完成前，禁止创建/写入任何待办文件。若 AI 跳过 Step 0 直接创建待办，视为严重违规，PM 应要求删除已创建文件并重新从 Step 0 执行。

> **滚存快照源**：拷贝 §0 / §0.5 / §0.6 时，源文件 = **该人最新存在的待办文件**（不限定前一日）。空窗日不生成任何占位文件。**N-44 B**：§0.6 只从最新文件整表拷贝再追加当日行；禁止回写历史日个人 md；禁止为回填建历史空目录；仅今天的能耗投喂才起链。

### 3.1 Step 0.5 共享人力提示（MANDATORY）

Step 0 之后、写入当日待办之前执行：

1. 读最新合法 `_index.md` **§1 花名册备注**「同时参与」。
2. 若待结转人同时参与项目 **≥ 2**，**必须**提示：「该人还在其他项目，请到其各自 ai 分别结转」。
3. 读 `context/project-context.md`「兄弟项目」段，给出具体项目名 / ai 路径指针。
4. 本包只结转本项目待办与本项目 §0.5/§0.6；**禁止代写他项目**。

### 3.1a 进组缩写查重（MANDATORY）

新成员进组或首次为本项目建待办前：

1. 读最新合法 `_index.md` **§6 TD 缩写映射**。
2. 拟用缩写已占用 → ASK（DF-015 一次问完）：「{缩写} 已被{原占用者}占用，{新人}建议：{拼音组合}/{姓全拼+名首}/{加数字} / 您指定？」先到先得，原占用者不改。
3. PM 确认后写入 §6 并冻结；不得静默改缩写（变更须写入 `pm-decisions.md`）。
4. `_index.md` §1 缩写列抄自 §6 现行值。一人多历史缩写：现行 + 历史别名，旧 TD 号不重编。

### 3.2 能耗滚存与停链（N-44 B）

- **起链**：有未办结待办 **或** **今天**有能耗投喂。滚存快照源 = **该人最新已存在文件**。空窗日（无待办且无今日投喂）不生成占位文件。
- **停链**：§0.5 末行出组日期已落定 **且** 连续 7 天无投喂 → 停止为其生成文件。
- **再起链**：停链后再次有日报 / 待办 / **今天**的投喂 → 重新起链（§0.5 追加新行）。
- 历史多日投喂：只在该人最新文件 §0.6 追加日期行，不建历史空目录。
- 能耗数值必须由 PM 投喂或对话检出，AI 禁自行推算；无数据标「—」（见 01 号 §1.6）。

### 3.3 Step 0.8 空闲检测（MANDATORY）

次日无待办且无日报 → **不自动出组**。标花名册「空闲」+ 写入 `pm-decisions.md` **块 8**，类型=人员状态提醒（派活 / 记离组 / 先放着）。查重键=**姓名+空闲**；命中则合并，不追加。

1. **检测对象**：仅扫「曾被派过活」的在岗人员——曾有待办文件，或曾出现在某日 `_index` **§3**。从未派活编制保持在岗，不进空闲台账。
2. 扫描最新合法 §1 中状态=在岗且命中上述范围的人：
   - 有未办结待办 → 正常结转
   - 有时间线内待办但无日报 → 催缴提醒（仅输出，不写文件）
   - 无任何时间线内待办且无日报 → 花名册标「空闲」+ 登记 `pm-decisions.md` 块 8（类型=人员状态提醒；查重键=姓名+空闲）
3. 空闲非终态，随时可回在岗。出组须 PM 确认。
4. 进组第一天、工作日历休息日不触发。
5. 对外白话：「{姓名} 手头没有任务也没写日报，已标为空闲。A. 给他派活；B. 他已离组，记一笔；C. 先放着」

### 3.4 禁止未来日与休息日（N-37 / N-38）

- **禁止**创建 `todos/{date>今天}/`。日报「明日/周末」只进当天个人 §2。
- **最新 index** = `{date | date≤今天 且存在 _index.md}` 的最大值。未来目录不参与判定。
- **休息日无人上班** → 不建该日目录。
- **休息日有人上班** → 只为实际上班的人建个人 md；当天 `_index` §1 仍从上一合法日拷贝全员，§3 只有上班者。下一天扫描名单仍用这份全员 §1。

## 4. 标记更新顺序（不可颠倒）

1. 先更新每人独立状态表（`_index.md` §2.3）
2. 再检查是否所有人都是"已确认"
3. 若全是"已确认" → 更新全局标记 `carryover_traced_until`（§2.2）
4. 写入日级完成标记 `carryover_done_for_today=true`（§2.1）
5. 输出"标记更新确认"，示例：
   - "已更新状态表：赵东洋→已确认(08/18), 胡康利→失败(7天内无文件)"
   - "全局标记：未更新（胡康利状态为失败）"
   - "日级完成标记：已设置 carryover_done_for_today = true"

**禁止行为**：
- 禁止在结转操作完成前更新标记
- 禁止只更新部分人的标记（必须所有人一起更新）
- 禁止在写入新待办后才更新标记（必须在写入前更新）

## 5. 编号硬约束与场景区分

**结转条目格式**：
- **待办编号不变（硬约束）**：编号中的日期 = 原始安排日期，序号不变
  - 示例：`TD-朱宇杰-20260817-002` 结转到 08/18 后仍为 `TD-朱宇杰-20260817-002`
  - **禁止**将结转待办重新编号为今天的日期（如 `TD-朱宇杰-20260818-003`）
- **开始时间 / 结束时间 / 原始结束时间原样搬运**（N-31）：禁止把开始时间改写成当天；不得自动对调倒挂的起止日期
- 备注区标注"结转自 {原始日期}"（格式见 `personal-daily-todo-template.md` 备注区）

**场景对比（AI 必须区分）**：

| 场景 | 操作 | 编号规则 | 示例 |
|---|---|---|---|
| **结转（跨天）** | 同一人，任务从昨天延续到今天 | **编号不变** | `TD-朱宇杰-20260817-002` → 今天仍为 `TD-朱宇杰-20260817-002` |
| **换人（转交）** | 任务从张三转给李四 | **生成新编号 + 溯源链** | `TD-张三-20260817-001` → `TD-李四-20260818-001`，溯源：`TD-张三-20260817-001 → TD-李四-20260818-001` |
| **新建** | 全新任务 | **新编号** | `TD-朱宇杰-20260818-001` |

> **编号硬约束适用范围**："编号中的日期 = 原始安排日期"仅适用于**同人结转**场景。**换人（转交）是例外**：新编号中的日期 = 转交日期，溯源链记录原始编号。

## 6. 错误处理规则（E1~E5）

| 编号 | 异常 | 处理 |
|---|---|---|
| E1 | 状态表缺失（§2.3 不存在） | 输出「⚠️ {D-1} 状态表缺失，视为所有人状态=待处理，扫描范围=date-7 到 date-1」→ 继续执行 Step 0 → 在当天 `_index.md` 创建完整状态表（所有人初始状态=待处理） |
| E2 | 状态表格式错误（列数不匹配/状态值非法） | 输出「⚠️ {D-1} 状态表格式错误，视为所有人状态=待处理」→ 继续执行 Step 0 → 在当天 `_index.md` 重建状态表 |
| E3 | 状态表中某人缺失（在 §1 花名册中但不在 §2.3） | 输出「⚠️ {姓名} 不在状态表中，视为状态=待处理」→ 为该人执行结转 → 在状态表中新增该人行 |
| E4 | 状态表中某人多出（在 §2.3 但不在 §1 花名册中） | 输出「⚠️ {姓名} 在状态表中但不在花名册中，保留其状态，不执行结转」→ 该人状态保持不变 |
| E5 | 结转操作中途失败（如文件写入错误） | 输出「⚠️ {姓名} 结转操作失败，状态保持=待处理」→ 不更新该人标记 → 继续处理其他人 → 在结转报告中记录失败原因 |

## 7. 状态机（完整转换）

每人独立状态只有 3 种：

| 当前状态 | 触发条件 | 新状态 |
|---|---|---|
| 待处理 | 该人结转成功（找到文件+扫描未办结+写入结转） | 已确认 |
| 待处理 | 该人追溯失败（7 天内无文件） | 失败 |
| 已确认 | 该人今天不在 §3（无文件）但仍在 §1 花名册 | 保持已确认 |
| 已确认 | 该人今天有待办文件但无未办结项 | 已确认 |
| 失败 | PM 手动修复（补充了缺失的文件） | 待处理 |
| 失败 | AI 重新追溯成功（找到之前缺失的文件） | 已确认 |

**全局标记转换**：
- `carryover_traced_until` = "无" → 所有人状态都为"已确认" → 更新为 date-1
- `carryover_traced_until` = D → 所有人状态都为"已确认" → 更新为 date-1
- 若有任何人状态为"失败"或"待处理" → 不更新全局标记

## 8. AI 自检清单（Step 0 完成后必须输出）

```
✅ 状态表读取确认：已读取 {D-1} 状态表，共 N 人
✅ 结转执行确认：已为 M 人执行结转，K 人跳过（无未办结待办）
✅ 编号验证（硬约束）：所有结转待办编号保持不变（日期=原始安排日期，序号不变）
   - 示例：TD-朱宇杰-20260817-002 结转后仍为 TD-朱宇杰-20260817-002，不是 TD-朱宇杰-20260818-003
✅ 三时间原样：开始/结束/原始结束未改写成当天
✅ 未建未来目录；扫描名单=最新合法 §1（date≤今天）；排除 archive/ backup/
✅ 标记更新确认：已更新状态表，全局标记={已更新/未更新}；carryover_done_for_today 恰好为 true
✅ 错误检查：无错误 / 发现 N 个错误（详见错误列表）
```

若任何一项自检失败 → 输出「⚠️ Step 0 自检未通过，请 PM 检查」。

## 9. 场景覆盖表

| 场景 | 全局标记 | 每人扫描范围 | 结果 |
|---|---|---|---|
| 正常工作日（昨天有 index，所有人已确认） | = `date-1` | 跳过 Step 0 | ✅ 快速路径 |
| 正常工作日（昨天有 index，部分人未确认） | < `date-1` | 每人按各自"最后确认日期"+1 扫描 | ✅ 只扫描未确认的人 |
| 周末后周一（昨天无 index） | < `date-1` | 向前找最近 index，每人按各自状态扫描 | ✅ 周五未办结结转 |
| AI 漏建某人昨天文件 | < `date-1` | 该人状态 = `失败`，扫描范围 = `date-7` 到昨天 | ✅ 该人未办结结转，不影响其他人 |
| 连续 3 天未交互 | < `date-1` | 向前找最近 index，每人按各自状态扫描 | ✅ 最近 index 的未办结结转 |
| 某人请假 5 天 | < `date-1` | 该人状态 = `待处理`，扫描范围 = `date-7` 到昨天 | ✅ 请假前未办结结转 |
| 首次使用（无任何 index） | 无 | 所有人扫描范围 = `date-7` 到昨天 | ⚠️ 输出提示，仅创建新待办 |
| 碰今天待办但 index 缺失或标记=部分 | 未完成 | 先全员 Step 0（N-43），再改点名的人 | ✅ 禁止残缺目录 |
| 休息日无人上班 | — | 不建目录，扫描跳过无 _index 的日历日 | ✅ N-38 |
| 日报写「明日=周末」 | — | 只进当天 §2，不建未来目录 | ✅ N-37 |
