# 共享人力与流转只读聚合（V-3 配套）

人员实体的**唯一事实源**在各成员项目待办体系：个人待办 §0 / §0.5 + `todos/{date}/_index.md`（§1 花名册、§6 TD 缩写）。**不再读** `resource-register` / `transfer-log`。本包只做跨项目指针与实时视图。

## 1. 集层允许的指针文件

`portfolio/resources/shared-resource-index.md`（跨项目共享资源索引）：

| 字段 | 说明 |
|------|------|
| 姓名 | |
| 参与子项目 | PRJ-NNN 列表（指向各项目 `_index` §1） |
| 共享状态 | 导航用：多项目共享 / 临时支援。人属性以各项目花名册为准 |

`portfolio/resources/transfer-index.md`（跨项目流转索引）：

| 字段 | 说明 |
|------|------|
| Transfer ID | 指向发生流转的项目待办 §0.5 行（兼容旧 `RTF-YYYYMMDD-NNN` 与时间戳号，仅作导航） |
| 姓名 | |
| 流转方向 | 如 PRJ-001 → PRJ-003 |
| 日期 | YYYY-MM-DD |

索引只作导航。禁止把可用性、排期、配置率、工时、能耗写入上述文件。同一人出现在 ≥2 个项目花名册时，应提示登记进 shared-resource-index（确认后只写指针）。索引不存在时，直接从各项目待办体系实时聚合，不创建空文件充数。

## 2. 动态视图（禁止落盘）

查询或集周报需要人员全景时，实时读：

- 各项目最新合法日 `todos/{date}/_index.md` **§1 花名册**（在组权威；date≤今天）
- 相关日期 `todos/{date}/{姓名}.md` 的 **§0**（联系方式/负责模块）与 **§0.5**（进出组）
- 各项目 `_index.md` **§6 TD 缩写映射**（互认、查重；不按缩写归并人）

输出可用性摘要、排期冲突、人力配置率。周报中的配置率表是当期快照，不得被后续查询当数据源。

**跨项目人员归并键**：按 **Owner 中文姓名** 归并，**不按 TD 缩写**。缩写从各项目 `_index` §6 读取，仅用于展示与查重。同一人跨项目缩写不一致（如储金晶企业通 CJJ / 全链通 SJJ）属合法现状；发现时一次性 SUGGEST 统一建议，不强制、不跨包写。

**流转**：从各项目个人待办 **§0.5** 进出组记录聚合（进组/出组日期、触发依据、备注含同时参与）。不读 transfer-log。

## 2a. 跨项目能耗 / 能效（只读）

跨项目问「某人能耗 / 成本损耗 / 能效」时：只读聚合该人在各已登记项目**最新**个人待办文件的 **§0.6**，按项目、按日并置。

- **禁止写入**任何项目 §0.6，禁止在 `portfolio/` 另建成本台账。
- **禁止**把外部工时表 / 填报表当作集层事实源。外部表出现在集层对话：只做分析+分流/V-9，**不写**成员 §0.6。集层 `portfolio/logs/` 记一行「已请某项目入库」。实际写入须到该项目 ChronoPM-Project 对话。
- 单位取自各项目 project-context，禁止写死；金额不落集层表。
- 与预算成本（各项目 `plans/budget.md`）两路不得混。

## 3. 漂移提示，不静默改项目文件

| 现象 | 本包行为 |
|------|----------|
| A 记王某同时在 B，B 无王某 | 提示双边不一致 → 内部 V-9（改 B 的 `_index` §1 / §0.5），不改 A 或 B |
| 同一人不同项目姓名写法不同 | 「可能存在身份映射问题」，请集经理确认是否同一人 |
| 分配比例跨项目合计 >100% | T1 冲突提示 |
| 共享人在一项目改为请假/离场，其他项目仍在岗 | 提示是否到其他项目同步（内部 V-9），不代同步 |
| 花名册与该项目 project-context 团队列表不一致 | 差异报告，不自动改任一侧 |
| 日报/周报出现未入花名册的人 | 候选资源变更，不自动入册 |

禁止：为「保持一致」把 A 项目字段覆盖到 B；禁止改成员项目待办「补一条集层看到的流转」。对外白话说明，不对用户说「建议更新清单」。

## 4. 资源风险只提示

命中下列条件时提示，并建议在**主归属项目** risk-register 登记（内部 V-9），本包不写风险实体：

| 编号 | 条件 | 等级 |
|------|------|------|
| RR-01 | 关键岗位无 B 角 | 高 |
| RR-02 | 同一人同时参与 ≥2 个 P0/P1 项目 | 高 |
| RR-03 | 请假但仍承担关键未办结待办 | 高 |
| RR-04 | 抽调导致原项目关键任务无人负责 | 高 |
| RR-05 | 各项目分配比例合计 >100% | 高 |
| RR-06 | 计划离场早于关键里程碑 | 中 |
| RR-07 | 核心岗位缺失（无后端/无测试/无产品，以该项目计划为准） | 高 |
| RR-08 | 连续流转 ≥3 次 | 中 |

## 5. 与单项目结转的边界

成员项目 ChronoPM-Project 在结转时提示「共享人力请到各项目分别结转」。本包：

- 不替任何项目做结转。
- 查询某人未办结待办时按 R18 跨项目列出，便于集经理看到漏结转，仍走内部 V-9。
