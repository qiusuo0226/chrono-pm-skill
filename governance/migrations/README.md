# ChronoPM 升级总索引（governance/migrations/）

> 本目录是 ChronoPM Skill 版本升级的**权威执行源**（D-18 决策，升级方案 v2.1 需求十一）。
> 信息架构：升级文件 = 完整执行步骤（权威源）；skill.json versionHistory = 摘要索引；`VERSION_CAPABILITIES`（migrate_workspace.py）= 运行时派生。

每个 `upgrade-to-{version}.md` 表示"从前一版本升级到该版本"的完整步骤。0.1.0 为初始版本，无升级文件。

## AI 升级执行流程（MANDATORY，20 号规则）

**触发条件**：AI 启动 Skill 时，或 PM 指示"升级工作区"时。

1. 读取工作区 `.skill-version.json` 中的 `skillVersion`
2. 读取 Skill 包 `VERSION` 文件获取目标版本
3. 若不一致 → 读取本 README 获取版本链
4. 确定从当前版本到目标版本需要经过哪些升级文件
5. 逐个读取并执行每个 `upgrade-to-{version}.md`
6. 每级执行完毕后更新 `.skill-version.json` 为该级版本
7. 全部执行完毕后验证工作区完整性

**禁止**：跳过中间版本直接升级（如从 1.0.0 直接跳到 2.0.0）。

**脚本辅助**：`python scripts/migrate_workspace.py --project-root <工作区根>` 自动执行目录/文件补齐与 v2.1.0 专项迁移（路径整合 + §7.3.2b 报告文件级迁移）；`--dry-run` 仅检测。内容级迁移（个人日报 → todos §3 工作日志段）必须由 AI 按升级文件步骤执行，脚本不代办。

## 异常处理

| 异常 | 处理 |
|---|---|
| 升级文件缺失（某个版本无 upgrade-to-{version}.md） | AI 输出「⚠️ 缺少升级到 X.X.X 的升级文件」，中止升级并提示 PM 补齐 |
| 迁移验证失败 | 保留旧结构，输出差异清单，人工介入后重试（禁止带失败继续删除旧数据） |
| 空源（旧路径无数据） | 登记"无数据，跳过"，不阻断其余迁移项 |

## 回填口径说明

历史升级文件于 v2.1.0 实施时按批次策略回填（升级方案 v2.1 §需求十一）：数据源为 `VERSION_CAPABILITIES`（新增目录/文件）、`skill.json` versionHistory（变更摘要/日期）、`CHANGELOG.md`（详细变更）、`governance/change-requests/CR-*.md`（推导依据）。批次 2/3 中标注"信息不全"的段落可在后续维护 CR 中补全，但文件本身必须存在以保证版本链连续。
